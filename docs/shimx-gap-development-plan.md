# 锐捷对齐 ShimX 能力开发计划

本文基于当前锐捷功能与 ShimX 能力差异，整理后续开发计划。优先级综合考虑用户价值、实现难度、对现有架构侵入性和与锐捷定位的匹配度。

## 评估口径

- **难易度**：低 / 中 / 高 / 很高。
- **价值**：低 / 中 / 高 / 很高。
- **优先级**：P0 必做、P1 高优先、P2 可排期、P3 暂缓或长期。
- **实现形态**：优先复用锐捷现有“魔改 Codex Desktop + 运行态 bridge + 内置资源同步”路线，不默认引入独立 Flutter 管理端。

## 总体路线

1. 先补“高价值、低到中等难度”的 Codex 内增强能力：模型体验、输入润色、轻量日志、插件/Skills 可见性。
2. 再补“数据管理能力”：会话导出、备份、恢复、导入。
3. 最后再评估“高复杂度平台能力”：多供应商、自动切换、Claude Bridge、内置 MCP Server、用户脚本系统。

## P0：继续维护的既有核心能力

### 1. 锐擎 API 与 Responses bridge

- **价值**：很高。
- **难度**：低到中，主要是兼容维护。
- **目标**：确保 GPT/Qwen Responses 直通稳定，Claude/GLM/Kimi/MiniMax/DeepSeek Chat 转换稳定。
- **验收**：主流模型可正常文本对话、工具调用、流式输出；错误信息能被用户理解。

### 2. 内置插件 marketplace

- **价值**：很高。
- **难度**：低到中。
- **目标**：保持内置“锐捷插件”同步稳定，不覆盖用户插件状态。
- **验收**：首次启动自动同步；manifest 升级后能更新；用户禁用/启用状态不被覆盖。

### 3. 生图 helper 与 imagegen skill 覆盖

- **价值**：很高。
- **难度**：低到中。
- **目标**：保持 `ruizhi-imagegen` 可用，优化失败提示、图片渲染和缺主题追问。
- **验收**：无需用户配置 Python SDK 或环境变量即可生成图片，并在会话中直接预览。

## P1：建议优先开发

### 1. 模型健康与延迟显示

- **价值**：高。
- **难易度**：中。
- **原因**：锐捷已有本地 bridge，天然可以统计请求耗时、失败率和最近错误，是后续自动切换和问题排查的基础。
- **建议拆分**：
  - bridge 记录每个模型最近 N 次请求耗时。
  - bridge 记录最近错误码、错误摘要、最近成功时间。
  - 页面增强在模型选择区域展示“最近延迟 / 健康状态”。
- **验收**：连续请求不同模型后，UI 能看到不同模型的最近延迟和错误状态。

### 2. reasoning 快捷控制

- **价值**：高。
- **难易度**：中。
- **原因**：当前模型目录已经补齐 reasoning 字段，但用户侧缺明显控制入口。
- **建议拆分**：
  - 确认 Codex 原生是否已有 reasoning 控件可复用。
  - 若没有，在 composer 附近增加轻量选择入口。
  - 请求进入 bridge 时确认 reasoning 字段透传或转换。
- **验收**：用户可在 UI 中切换 low/medium/high，并反映到请求。

### 3. 输入框润色

- **价值**：高。
- **难易度**：中。
- **原因**：普通用户感知强，且不改变底层数据结构。
- **建议拆分**：
  - 页面增强定位 composer 输入框。
  - 增加“润色”按钮和风格选项：简洁、正式、口语、详细。
  - 调用当前锐擎模型生成候选，展示原文/润色后对比。
  - 用户确认后替换输入框内容。
- **验收**：输入中文或英文后可生成候选，确认后替换，不自动发送。

### 4. 单会话 Markdown 导出

- **价值**：高。
- **难易度**：中。
- **原因**：已有 `markdownExport` 开关，应优先完成用户可见闭环。
- **建议拆分**：
  - 找到当前 thread 对应 rollout JSONL。
  - 转换用户消息、助手消息、工具调用、工具结果。
  - 提供“导出 Markdown”入口。
- **验收**：当前会话可导出为 Markdown，内容顺序正确，工具调用可读。

### 5. 插件状态面板

- **价值**：高。
- **难易度**：中。
- **原因**：锐捷已有内置 marketplace，但用户缺少“是否已同步、版本多少、插件是否可用”的可视反馈。
- **建议拆分**：
  - 读取内置 marketplace manifest。
  - 读取 `CODEX_HOME/.tmp/marketplaces` 同步结果。
  - 展示插件名称、版本、同步状态、错误原因。
- **验收**：插件页能清晰显示内置插件是否已安装/已更新。

## P2：可排期增强

### 1. 应用内日志面板

- **价值**：中。
- **难易度**：中。
- **建议**：优先记录 bridge 请求、模型转换、插件同步、生图 helper 调用、更新检查结果。
- **验收**：用户可打开日志面板，按级别查看和复制最近日志。

### 2. 托盘控制

- **价值**：中。
- **难易度**：中。
- **建议**：Electron 主进程增加托盘菜单：显示窗口、重启应用、退出。
- **验收**：关闭窗口行为和托盘菜单符合 Windows/macOS 用户预期。

### 3. HTML/raw JSONL 导出

- **价值**：中。
- **难易度**：中。
- **建议**：复用 Markdown 导出的解析层，增加格式化输出。
- **验收**：同一会话可导出 Markdown、HTML、raw JSONL。

### 4. Claude Code 会话只读浏览

- **价值**：中。
- **难易度**：中。
- **建议**：先只读扫描和导出，不做 Bridge 绑定。
- **验收**：能按项目列出 Claude Code 会话，并查看/导出消息。

### 5. 工具过滤关键词

- **价值**：中。
- **难易度**：中。
- **建议**：在 bridge 请求层做 tools 过滤，并提供简单配置入口。
- **验收**：配置关键词后，对应工具不会出现在发给上游模型的 tools 列表中。

### 6. 会话备份库

- **价值**：高。
- **难易度**：高。
- **建议**：先服务“删除/恢复前自动备份”，不要一开始做完整备份管理 UI。
- **验收**：任何会话破坏性操作前，都能在本地备份目录找到可恢复材料。

## P3：暂缓或需产品决策

### 1. 多供应商管理

- **价值**：高。
- **难易度**：很高。
- **暂缓原因**：与锐捷“默认锐擎 API 入口”的产品定位存在冲突。
- **决策点**：锐捷是否要变成通用 Codex Provider 管理器，还是坚持锐擎专用发行版。

### 2. 自动切换 / 最快优先

- **价值**：中到高。
- **难易度**：很高。
- **暂缓原因**：依赖多供应商体系和健康检测体系。
- **建议**：先做单 provider 多模型健康展示，再评估是否需要自动切换。

### 3. 内置 MCP Server 与 Claude Bridge

- **价值**：高。
- **难易度**：很高。
- **暂缓原因**：涉及本地服务、Codex MCP 配置、Claude JSONL 解析、上下文注入策略。
- **建议**：先做 Claude 会话只读浏览，验证用户需求后再做 Bridge。

### 4. 用户脚本系统

- **价值**：中。
- **难易度**：很高。
- **暂缓原因**：需要脚本目录、编辑器、权限边界、注入生命周期和 API 稳定性承诺。
- **建议**：锐捷短期保持内置增强脚本，不开放完整用户脚本生态。

### 5. JSONL/ZIP 会话导入与物理删除

- **价值**：中。
- **难易度**：很高。
- **暂缓原因**：直接写 Codex 数据库和 rollout 文件，数据损坏风险高。
- **建议**：先做导出和自动备份，再做导入/物理删除。

## 推荐里程碑

### M1：模型与输入体验增强

- 模型最近延迟展示。
- 模型健康状态记录。
- reasoning 快捷控制。
- 输入框润色。

### M2：可见性与排障

- 插件状态面板。
- 应用内日志面板。
- bridge 错误提示优化。
- 生图失败提示优化。

### M3：会话基础管理

- 当前会话 Markdown 导出。
- HTML/raw JSONL 导出。
- 破坏性操作前自动备份。
- 会话备份目录说明与恢复脚本。

### M4：扩展生态增强

- Skills 只读列表。
- 本地 ZIP/目录插件导入。
- 工具过滤关键词。
- Claude Code 会话只读浏览。

### M5：长期平台能力评估

- 多供应商管理。
- 自动切换策略。
- 内置 MCP Server。
- Claude Bridge。
- 用户脚本系统。

## 近期建议执行顺序

1. **模型健康与延迟显示**：复用 bridge，收益高，风险可控。
2. **输入框润色**：用户感知强，适合快速做成亮点。
3. **单会话 Markdown 导出**：补齐当前已有 `markdownExport` 的闭环。
4. **插件状态面板**：把锐捷已有 marketplace 能力可视化。
5. **应用内日志面板**：为后续模型、插件、生图排障打基础。
